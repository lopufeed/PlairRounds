# Инструкции для Codex

Этот репозиторий — шаблон небольших браузерных игр для PLAIR Games. Пользователь хочет быстро создавать и публиковать игры, которые работают на телефонах и компьютерах.

## Технологии и запуск

- Используй Vite и обычные JavaScript, HTML и CSS. Не добавляй крупный движок или зависимости без необходимости.
- Запуск: `npm run dev`. Проверка сборки: `npm run build`. Публикуемые файлы находятся в `dist/`.
- GitHub Pages деплоится workflow из `.github/workflows/deploy.yml`.

## Требования к каждой игре

- Игровой цикл и первая игровая сессия должны быть понятны без регистрации и установки.
- Поддерживай мышь, клавиатуру и сенсорное управление, где это уместно; не перехватывай системные жесты за пределами игрового поля.
- Макет должен подстраиваться под узкий экран и портретную ориентацию. Учитывай безопасные области и DPR холста.
- Держи суммарный размер сборки до 10 МБ, желательно до 5 МБ. Избегай лишних библиотек и больших медиафайлов.
- Сохраняй `cover.png` / `cover.jpg` / `cover.webp` и `cover-square.*` в корне рядом с `index.html`, если пользователь добавил обложки.
- Не удаляй `plair-verify` метатег или SDK PLAIR, если пользователь настроил их. Событие окончания раунда может вызывать `PLAIR.score(points)` только при наличии SDK.
- Не придумывай и не подставляй код подтверждения PLAIR. Оставляй пользовательский placeholder до получения настоящего кода.
- Для очков с меньшим результатом лучше используй `PLAIR.score(value, { lowerIsBetter: true })`.

## Стиль изменений

- Сохраняй текущую структуру простого проекта; сначала изучи существующую механику и соглашения.
- Визуально делай интерфейс ясным и дружелюбным, с крупными зонами касания и заметным состоянием игры.
- Не добавляй внешние сетевые ресурсы в рантайм без явной нужды; игра должна грузиться быстро и оставаться самодостаточной.
- Не запускай тесты, если пользователь прямо не просит проверить. Если пользователь просит проверить, предпочитай `npm run build` и ручной сценарий запуска.
